## 1. System Overview

**InstaAutoAI** is a fully local multi-agent pipeline that accepts a user content brief (topic + niche + tone) and autonomously produces a complete Instagram post package:

- 🖼️ **Static Post** — generated by `Z-Image-Turbo` (text-to-image)
- 🎬 **Reel Clip** — generated by `LTX-2.3 GGUF` via ComfyUI (text/image-to-video)
- ✍️ **Caption + Hashtags** — generated by `Qwen3:8B` via Ollama

The system is orchestrated by a **LangGraph state machine** running specialised **CrewAI agents** at each node. A **Django REST API** exposes the pipeline, and a single-file **Tailwind + Alpine.js dashboard** provides the user interface with live WebSocket progress streaming.

No external API calls. No cloud dependencies. No ongoing costs.

## 2. Tech Stack

| Layer | Technology | Version |
|---|---|---|
| **Orchestration** | LangGraph `StateGraph` | `>=1.0.0` |
| **Agent Framework** | CrewAI with `Process.sequential` | `>=0.80.0` |
| **LLM Backbone** | Qwen3:8B Q4_K_M via Ollama | OpenAI-compat endpoint |
| **Image Model** | Z-Image-Turbo (`ZImagePipeline`) | diffusers source install |
| **Video Model** | LTX-2.3 GGUF (Quantstack) via ComfyUI | `http://localhost:8188` |
| **Backend** | Django 5.x + DRF + django-channels | `>=5.1` |
| **Frontend** | HTML + Tailwind CDN + Alpine.js | Single-file, no build step |
| **Task Queue** | Celery + Redis (or django-channels in-memory) | replaces `asyncio.create_task` |
| **DB** | PostgreSQL (dev + prod) | avoids SQLite concurrency issues |
| **VRAM Gate** | Redis-backed distributed lock | cross-process safe |
| **Python** | 3.11+ (Windows 10/11 x64) | — |
| **CUDA** | cu124 · `torch>=2.5+cu124` · bf16 active | — |

> ⚠️ **Do NOT use `asyncio.create_task` inside Django views** — use Celery for background pipeline execution to avoid orphaned tasks and silent failures.

> ⚠️ **Do NOT use an in-process `asyncio.Lock` as the VRAM gate** — it is process-local and provides zero mutual exclusion across Celery workers. Use a Redis-backed distributed lock (`redis-py` `SET NX EX`).

## 3. VRAM Budget

| Component | VRAM Usage | Notes |
|---|---|---|
| Qwen3:8B Q4_K_M (Ollama) | ~5.6 GB | Always resident during pipeline |
| Z-Image-Turbo (active inference) | ~6–7 GB | `enable_sequential_cpu_offload()` required |
| LTX-2.3 GGUF (ComfyUI subprocess) | ~6–7 GB | Sysmem fallback via NVIDIA Control Panel |
| **Hard ceiling** | **7.8 GB** | 200 MB reserved for OS/driver overhead |

**Critical rule:** Z-Image-Turbo and LTX-2.3 **must never be loaded simultaneously**.  
Ollama must be unloaded (or its model evicted) before any diffusion model loads.  
Enforced by `VRAMManager` distributed lock — one model in VRAM at any time.

## 5. Pipeline Architecture

### 5.1 VRAM Infrastructure

#### `VRAMManager` — Distributed Singleton

```python
# pipeline/vram_manager.py

class VRAMManager:
    """
    Redis-backed distributed lock ensures only one model occupies VRAM
    across all Celery workers and Django processes.
    """
    LOCK_KEY = "instaAutoAI:vram_lock"
    LOCK_TTL = 3600  # 60 min max hold (covers LTX-2.3 video gen)

    async def load_model(self, model_key: str, loader_fn: Callable) -> Any:
        # 1. Acquire Redis lock (SET NX EX) — blocks if another model is active
        # 2. Log VRAM before: torch.cuda.memory_allocated()
        # 3. torch.cuda.empty_cache() + gc.collect()
        # 4. Call loader_fn() to load model
        # 5. Log VRAM after — record delta
        # 6. Return loaded model
        # 7. Caller is responsible for del model + empty_cache() + release lock
```

**Why Redis lock, not `asyncio.Lock`:** An `asyncio.Lock` is process-local. When Celery spawns multiple workers (even on the same machine), each worker has its own lock instance — they cannot see each other's lock state. Two jobs submitted in quick succession would both "acquire" their local lock and both load models into VRAM simultaneously, causing an OOM crash. A Redis lock is shared across all processes on the machine.

#### `OllamaLLMClient` — Shared Singleton

```python
# pipeline/llm_client.py

client = AsyncOpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama"
)
# model="qwen3:8b", temperature=0.7, num_ctx=4096

# Startup health check:
# GET http://localhost:11434/api/tags
# → raise ServiceUnavailableError("Run: ollama serve") if unreachable
```

**Shared across all CrewAI agents** — never instantiate per-agent. Qwen3:8B occupies ~5.6 GB VRAM; multiple instances would OOM immediately.

### 5.2 LangGraph State Machine

#### Pipeline State Schema

```python
# pipeline/state.py

class PipelineState(TypedDict):
    request:       GenerationRequest
    strategy:      Annotated[str, "content_strategy_output"]
    visual_prompt: Annotated[dict, "diffusion_prompt"]       # {positive, negative}
    image_path:    Annotated[str | None, "saved_image_path"]
    video_path:    Annotated[str | None, "saved_video_path"]
    caption:       Annotated[str, "final_caption"]
    hashtags:      Annotated[list[str], "hashtag_list"]
    error:         Annotated[str | None, "error_message"]
    vram_log:      Annotated[list[dict], operator.add]       # accumulates across nodes
```

#### Node Map

```
[START]
   │
   ▼
[strategy_node]         ← CrewAI: ContentStrategistAgent
   │
   ▼
[visual_prompt_node]    ← CrewAI: VisualDirectorAgent
   │
   ▼
[image_gen_node]        ← Z-Image-Turbo via VRAMManager
   │
   ├── (if output_format includes "reel")
   │      ▼
   │   [video_gen_node] ← LTX-2.3 GGUF via ComfyUI API
   │
   ▼
[caption_node]          ← CrewAI: CopywriterAgent
   │
   ▼
[hashtag_node]          ← CrewAI: HashtagResearcherAgent
   │
   ▼
[export_node]           ← assembles GenerationResult, writes to DB
   │
[END]

         ↕  (any node → on error)
   [error_handler_node] → [END]
```

Error routing: a `add_conditional_edges` check on `state["error"]` at every node — if set, immediately route to `error_handler_node` which logs, updates `GenerationJob` status to `"failed"`, and terminates.

#### Checkpointing

```python
# pipeline/runner.py

from langgraph.checkpoint.sqlite import SqliteSaver

graph = graph_definition.compile(
    checkpointer=SqliteSaver(conn=get_checkpoint_db_conn())
)

await graph.ainvoke(
    initial_state,
    config={"configurable": {"thread_id": job_id}}
)
```

> **Why checkpointing is non-negotiable:** LTX-2.3 video generation on 8GB VRAM takes 10–45 minutes. Without `SqliteSaver`, any crash (power, OOM, Windows update) loses all prior pipeline work and forces a full restart. With checkpointing, the pipeline resumes from the last completed node.

> ⚠️ Use a **dedicated SQLite file for checkpoints only** — separate from the main Django database. This avoids `OperationalError: database is locked` from concurrent Django ORM writes.

### 5.3 CrewAI Agents

All agents defined in `pipeline/crew.py` using `crewai.Crew(process=Process.sequential)`. All share the single `OllamaLLMClient`.

---

#### Agent 1 — `ContentStrategistAgent`

| Field | Value |
|---|---|
| **Role** | Instagram Content Strategist |
| **Goal** | Analyze topic/niche/tone brief → produce structured content strategy |
| **Output Format** | JSON: `{ hook, value_prop, cta, visual_mood, caption_angles: list[str] }` |
| **Tools** | None (pure reasoning) |

The strategy output becomes the shared foundation for all downstream agents. Three `caption_angles` are produced; the best one is selected by the CopywriterAgent.

---

#### Agent 2 — `VisualDirectorAgent`

| Field | Value |
|---|---|
| **Role** | AI Image Prompt Engineer |
| **Goal** | Convert `visual_mood` → optimised Z-Image-Turbo diffusion prompt |
| **Output Format** | `{ "positive_prompt": str (max 120 tokens), "negative_prompt": str }` |
| **Tools** | None |

Positive prompt must include: subject, environment, lighting, colour palette, camera angle, and style modifiers (`photorealistic, 8K, Instagram aesthetic`).  
Negative prompt is always: `"blurry, watermark, text overlay, low quality, distorted"`.

---

#### Agent 3 — `CopywriterAgent`

| Field | Value |
|---|---|
| **Role** | Instagram Caption Writer |
| **Goal** | Write a platform-native caption from the best `caption_angle` |
| **Output Format** | Plain string — hook (≤8 words) + body + CTA. No hashtags in body. |
| **Tools** | None |

Post-processing in `export_node`: if `len(caption) > 2200`, truncate at the last complete sentence before the limit and append `"..."`.

---

#### Agent 4 — `HashtagResearcherAgent`

| Field | Value |
|---|---|
| **Role** | Instagram Hashtag Strategist |
| **Goal** | Generate exactly `hashtag_count` hashtags in a balanced category mix |
| **Output Format** | `list[str]` — each prefixed with `#` |
| **Tools** | None |

Category mix target: **30%** broad (>1M posts) · **50%** mid-tier (100K–1M posts) · **20%** niche (<100K posts).

> ⚠️ **Reach estimates are approximate** — Qwen3:8B has no live Instagram API access. Hashtags are ordered by *category tier*, not verified reach data. Treat output as an informed starting point, not analytics-grade data.

### 5.4 Generative Model Nodes

#### `image_gen_node` — Z-Image-Turbo

```python
# pipeline/nodes/image_gen.py

async def image_gen_node(state: PipelineState) -> PipelineState:
    try:
        async with vram_manager.acquire():          # Redis distributed lock
            pipe = ZImagePipeline.from_pretrained(
                "Tongyi-MAI/Z-Image-Turbo",
                torch_dtype=torch.bfloat16           # Windows: fallback to float16
            )                                        # if RuntimeError("float8")
            pipe.enable_sequential_cpu_offload()     # CRITICAL for 8GB VRAM

            result = pipe(
                prompt=state["visual_prompt"]["positive_prompt"],
                negative_prompt=state["visual_prompt"]["negative_prompt"],
                num_inference_steps=8,               # Optimal for Z-Image-Turbo
                guidance_scale=3.5,
                height=get_height(state["request"]["aspect_ratio"]),
                width=get_width(state["request"]["aspect_ratio"])
            )

            image_path = save_image(result.images[0], state["request"]["job_id"])

    except torch.cuda.OutOfMemoryError:
        # Retry once at 512×512 with resolution_fallback flag
        ...
    finally:
        del pipe
        torch.cuda.empty_cache()
        gc.collect()
        # Lock released by context manager

    return {**state, "image_path": image_path}
```

> **Expected generation time:** 3–8 minutes per image at 1024×1024 with `enable_sequential_cpu_offload()` on an RTX 4060 8GB. The frontend must communicate this wait time to users — do not imply near-realtime generation.

#### Resolution by Aspect Ratio

| `aspect_ratio` | Width | Height |
|---|---|---|
| `1:1` | 1024 | 1024 |
| `4:5` | 896 | 1152 |
| `9:16` | 768 | 1344 |

#### `video_gen_node` — LTX-2.3 GGUF via ComfyUI

```python
# pipeline/nodes/video_gen.py

async def video_gen_node(state: PipelineState) -> PipelineState:
    # 1. Health check: GET http://localhost:8188/  → httpx.ConnectError
    #    If offline: set video_path=None, flag metadata, skip node

    # 2. Upload image_path to ComfyUI input folder

    # 3. POST http://localhost:8188/api/prompt
    #    Payload: workflows/ltx_i2v_portrait.json
    #    Injected values:
    #      - image node: uploaded image filename
    #      - positive prompt: state["visual_prompt"]["positive_prompt"]
    #      - resolution: 544×960 (9:16 portrait)
    #      - frames: 97 (4s @ 24fps)
    #      - precision: FP8 + tiled VAE decode

    # 4. Poll GET http://localhost:8188/api/history/{prompt_id}
    #    Until status == "success" or timeout (60 min)

    # 5. Copy output MP4 to media/jobs/{job_id}/reel.mp4
```

> **Why ComfyUI subprocess, not Python SDK:** ComfyUI runs as a separate OS process and manages its own VRAM + sysmem fallback policy (set via NVIDIA Control Panel: `CUDA → Sysmem Fallback Policy → Prefer Sysmem Fallback`). This isolates the Django/Celery process from LTX-2.3's aggressive memory use and prevents OOM from cascading into the main application.

> **Expected generation time:** 10–45 minutes for a 4-second 544×960 clip on RTX 4060 8GB with GGUF quantization + sysmem fallback.

#### API Endpoints — `jobs/views.py`

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/api/v1/generate/` | Create job, enqueue Celery task, return `{ job_id, status: "queued" }` |
| `GET` | `/api/v1/jobs/{job_id}/` | Fetch current job state + result |
| `GET` | `/api/v1/jobs/` | List last 20 jobs (for history sidebar) |
| `GET` | `/api/v1/jobs/{job_id}/vram/` | Latest VRAM snapshot (polled by frontend) |
| `WS` | `ws://localhost:8000/ws/jobs/{job_id}/` | Live `node_complete` + `progress` events |

> **Concurrency limit:** `POST /api/v1/generate/` must return `HTTP 503 Service Unavailable` (with `Retry-After: 300` header) when a job is already running. One job at a time on 8GB VRAM — do not silently queue.

#### Pipeline Runner — `pipeline/runner.py`

```python
# Called by Celery worker — NOT by Django view directly

@celery_app.task
def run_pipeline_task(job_id: str, request_data: dict):
    asyncio.run(_run(job_id, request_data))

async def _run(job_id: str, request: GenerationRequest):
    job = await GenerationJob.objects.aget(pk=job_id)
    job.status = "running"
    await job.asave()

    try:
        graph = build_graph().compile(
            checkpointer=SqliteSaver(conn=get_checkpoint_conn())
        )
        result = await graph.ainvoke(
            {"request": request},
            config={"configurable": {"thread_id": job_id}}
        )
        # Write result to GenerationJob
    except Exception as e:
        job.error_message = str(e)
        job.status = "failed"
        await job.asave()
```

#### WebSocket Consumer — `jobs/consumers.py`

Streams events to the frontend as pipeline nodes complete. The `strategy_node`, `image_gen_node`, etc., each call a shared `emit_progress(job_id, node_name, progress_pct)` helper that sends to the channel layer.

## 8. Edge Cases & Failure Handling

| Failure Mode | Handler | Location |
|---|---|---|
| **VRAM OOM during image gen** | Catch `torch.cuda.OutOfMemoryError` → flush VRAM → retry at 512×512 → set `generation_metadata.resolution_fallback = true` | `image_gen_node` |
| **ComfyUI offline during video gen** | `httpx.ConnectError` on pre-node health check → `video_path = None` → continue pipeline → flag in metadata | `video_gen_node` |
| **Ollama not running** | Ping `/api/tags` at Django startup → raise `ServiceUnavailableError("Run: ollama serve")` | `llm_client.py` startup |
| **LangGraph checkpoint corruption** | Catch `Exception` in `runner.py` → delete checkpoint file by `thread_id` → re-run from scratch → log incident | `runner.py` |
| **Caption > 2,200 chars** | Truncate at last complete sentence before limit → append `"..."` | `export_node` |
| **Z-Image float8 error on Windows** | Catch `RuntimeError` containing `"float8"` → retry with `torch.float16` | `image_gen_node` |
| **Qwen3 context overflow** | Pre-check token count (Qwen tokenizer) before each LLM call → if >3,500, summarise `strategy` output before passing downstream | All agent nodes |
| **Second job submitted while one running** | Return `HTTP 503` with `Retry-After: 300` header before creating a new `GenerationJob` | `POST /api/v1/generate/` view |
| **Redis unavailable (lock service down)** | Catch `redis.ConnectionError` at startup → raise with message: `"Start Redis: redis-server"` | `vram_manager.py` startup |

## 9. Success Criteria

| Criterion | Measurement |
|---|---|
| Pipeline completes end-to-end | `GenerationJob.status == "done"` for a standard `"both"` format request |
| Image generated without OOM | Z-Image-Turbo completes at target resolution with `enable_sequential_cpu_offload()` — no `torch.cuda.OutOfMemoryError` |
| Caption is Instagram-compliant | `len(caption) <= 2200` · contains hook + body + CTA · no hashtags in body |
| Hashtags are correctly formatted | All items start with `#` · count matches `hashtag_count` · correct category mix |
| Frontend shows live progress | WebSocket `node_complete` events update DAG node colours within 2s of node completion |
| Pipeline is resumable | Kill process mid-run → restart → `ainvoke` resumes from last `SqliteSaver` checkpoint |
| No concurrent model loads | `VRAMManager` Redis lock log shows zero overlapping acquisition windows across any job run |
| VRAM stays within budget | `torch.cuda.max_memory_allocated()` never exceeds 7.8 GB during any single job |
| Concurrency guard active | Second `POST /api/v1/generate/` while job is running returns `HTTP 503` |

## 10. Anti-Patterns to Avoid

| Anti-Pattern | Why It Fails |
|---|---|
| Loading Z-Image + LTX simultaneously | Instant OOM — 6B + 20.9B params cannot coexist in 8GB VRAM |
| `pipe.to("cuda")` without `enable_sequential_cpu_offload()` | Full Z-Image model loads to VRAM before first inference step — immediate OOM |
| New Ollama client per CrewAI agent | Ollama spawns additional model processes, thrashing VRAM/RAM |
| LangGraph without `SqliteSaver` checkpointer | 10–45 min video node failure loses all prior work, forces full restart |
| Base64 images in Django `JSONField` | `JSONField` is for structured metadata — use `FileField` + `media/` for binary assets |
| `Process.hierarchical` in CrewAI | Adds an LLM manager layer that doubles Ollama calls and VRAM pressure |
| `num_ctx=32768` in Ollama | ~3 GB VRAM for KV cache alone — hard cap at 4,096 |
| `torch.cuda.empty_cache()` before `del pipe` | GC has not released the model reference — `empty_cache()` is a no-op until all refs are gone |
| Generating 1080p video via LTX-2.3 on 8GB | Requires 12 GB+ minimum — always target 544×960 at GGUF precision |
| `asyncio.create_task` inside Django views | Task orphaned when request completes — use Celery for all background pipeline work |
| In-process `asyncio.Lock` as VRAM gate | Process-local — zero mutual exclusion across Celery workers |
| Using AutoGen as multi-agent framework | Maintenance mode since 2026 — use CrewAI Flows |
| `tiktoken` for Qwen3 token counting | Wrong vocabulary — off by 10–30%, silent context overflows |
| SQLite as main application DB | Concurrent Django ORM + channels + LangGraph writes cause `OperationalError: database is locked` — use PostgreSQL |

## 11. Known Constraints & Corrections

### Hardware Realities

- **LTX-2.3 on RTX 4060 8GB is below the official minimum** (12 GB VRAM). It is only achievable via GGUF quantization + NVIDIA sysmem fallback policy. Native inference is not possible.
- **Z-Image-Turbo officially targets 16 GB VRAM.** On 8 GB, `enable_sequential_cpu_offload()` is mandatory, not optional. Expect 3–8 minute generation times per image (not seconds).
- **"100% Local" applies to image generation.** Full LTX-2.3 video generation requires extensive RAM offloading and will be slow (10–45 min/clip). A cloud fallback endpoint is architecturally optional but may be worth implementing.

### Model Role Clarification

| Model | Type | Used For |
|---|---|---|
| Z-Image-Turbo | Text-to-image / image-to-image | Instagram static posts |
| LTX-2.3 GGUF | Image-to-video | Instagram Reels clips |
| Qwen3:8B | LLM (text) | Strategy, prompts, captions, hashtags |

These are three separate models with distinct roles. They are **never loaded simultaneously**.
